# بنك الدم: فترة اختيارية وزمرة واحدة للواقعة

هذا التصحيح يبني على توحيد الأشخاص والوقائع في PR #18. وجود فترة تقارير، حالتها، أو تداخلها لم يعد شرطًا لتسجيل تبرع أو صرف أو نقل دم أو تصحيحها. يبقى التاريخ الفعلي الصحيح غير المستقبلي وفق توقيت المنشأة شرطًا مستقلًا، مع الصلاحيات والعزل وUUID وlock_version وربط مرحلتي الصرف والنقل.

## الترحيل والتشغيل

Migration الجديدة: `2026_09_15_000001_make_blood_bank_periods_optional.php`. تعدّل فقط nullability لـ`reporting_period_id` في `blood_bank_events` و`blood_donations` و`blood_transfusions`. تحتفظ بأسماء المفاتيح الخارجية المركبة `(reporting_period_id, facility_id)` وفهارسها وقيم كل سجل. لا تستخدم تعطيل فحص المفاتيح، ولا تعيد كتابة البيانات. تتحقق من المخطط المتوقع قبل أي DDL.

على تثبيت سبق ترقيته إلى PR #18، أمر الترقية المطلوب هو `php artisan migrate --force` ضمن إجراءات التشغيل المصرح بها، مع نسخة احتياطية ومراجعة المعتادة. لا يلزم seeder أو صلاحية جديدة أو إعادة المصالحة لهذا التصحيح. يلزم بناء frontend الجديد باستخدام `npm run build` وإعداد `LARAVEL_API_URL` المعتمد. هذه تعليمات تشغيل؛ لم ننفّذها على الإنتاج ولم ننشر.

السجلات الجديدة تحفظ فترة NULL. التعديل لا يكتب عمود الفترة مطلقًا في المسار الموحد، حتى إذا أصبح التاريخ المصحح خارج الفترة القديمة. الرابط القديم معلومة تاريخية وليس مرجعًا لتصفية التاريخ الحالي. لا يتم إنشاء فترة أو فتحها أو اختيارها تلقائيًا. تبقى قواعد الفترات في الأقسام الأخرى كما هي.

`down()` يفحص الجداول الثلاثة قبل تغيير أي منها. إن وُجدت واقعة بلا فترة يرفض rollback صراحةً، دون حذفها أو اختلاق فترة. يمكن إرجاع NOT NULL فقط عندما تكون جميع القيم غير فارغة أصلًا. بعد استخدام المخطط الجديد تكون خطة التراجع الاحتفاظ بالمخطط المتوافق أو استعادة نسخة مراجعة؛ لا تنفّذ إعادة تعيين فترات عشوائية لإجبار rollback. DDL على MariaDB ليس transaction متعددة الجداول؛ عند انقطاع ترحيل افحص المخطط وأعد تطبيقه، دون تعطيل القيود.

## الإدخال والتقارير

تعرض نافذة الواقعة مجموعة واحدة «زمرة الدم لهذه الواقعة». اختيار شخص موجود يملؤها من قيمه الحالية مرة واحدة؛ تعديلها، حتى إلى مجهول، يبقى في المسودة عند تحديث الخيارات أو الحوارات الفرعية أو إعادة الجلب. اختيار شخص مختلف يمسح القيم السابقة ويحمّل قيم الجديد، والاستجابات المتأخرة لا تعيد شخصًا سابقًا. تعديل واقعة يعرض قيمها المحفوظة وحدها.

إنشاء شخص مع أول واقعة يحفظ قيم الزمرة العليا نفسها في الشخص والواقعة ضمن المعاملة القائمة، حتى لو أرسل عميل آخر قيمًا متناقضة داخل `person`. هوية شخص موجود لا تُعدّل تلقائيًا، بما فيها إعادة استخدام patient_id قائم. لا نفترض زمرة مجهولة: التبرع ما زال يتطلب ABO وRh، والاستفادة تسمح بعدم معرفتهما. تبقى الكميات بالكيلوغرام والفحوص الاختيارية بحالة فقط كما كانت.

استعلامات `BloodEventQueries` و`BloodEventReports` وتقارير الملفات القديمة لا تربط بفترة تقارير لاستبعاد NULL. تعتمد تواريخ الوقائع والفلاتر؛ السجل والإجماليات وتقارير الأشخاص والوقائع PDF/Excel تشمل الجديد بلا فترة. استهلاك `blood_transfusions` في `CatalogBeneficiaries` مستقل عن الفترة؛ اختبار يقارن تفاصيل الخدمات والإجراءات والصفوف والإجماليات قبل وبعد جعل الفترة NULL، دون تغيير أهلية الوقائع أو تعريف المستفيد.

## إعادة التحقق بأمان

استخدم `.env.testing` أو متغيرات تشغيل محلية بلا أسرار في Git، وMySQL driver وقاعدة اختبار منفصلة، مع `TEST_DATABASE_CONFIRMED=true` وتطابق `TEST_DATABASE_NAME` و`TEST_DATABASE_HOST`. ابدأ بـ:

```sh
php artisan test-db:check --connect --env=testing
php artisan test --env=testing --filter='BloodEventsTest|BloodBankPeriodMigrationTest|BloodBankMigrationConcurrencyTest|BloodBankProfileWorkflowTest|BloodBankReportsTest|BloodEventUpgradeTest|CatalogApiTest'
./vendor/bin/pint --dirty --test
```

اختبار الترحيل يستعمل مخطط NOT NULL مأهولًا ببيانات اصطناعية ومراجع تاريخية، ثم يتحقق من الحقول والمفاتيح والترقية وrollback الآمن ورفض ربط فترة منشأة أخرى. اختبارات Laravel تستخدم RefreshDatabase/DatabaseMigrations بعد حاجز الأمان؛ لا تشغّلها أثناء اختبارات HTTP على القاعدة نفسها.

ابنِ Next standalone جديدًا نحو Laravel الاختباري، وانسخ `.next/static` و`public` إلى مسارات standalone، وشغّل الخادمين على loopback. ثم من frontend، مع متغيرات قاعدة الاختبار نفسها وPlaywright المحلي:

```sh
node --test --test-concurrency=1 tests/blood-bank-periods-live.test.mjs tests/blood-bank-live.test.mjs tests/blood-bank-reports-live.test.mjs
npx tsc --noEmit
npm run lint
npm run build
git diff --check
```

تستخدم اختبارات المتصفح API الفعلية عبر Next → Laravel → MariaDB. تأخير fetch لا يستبدل استجابة Laravel؛ يستخدم لاختبار الردود المتأخرة فقط. لقطات النموذج تحفظ محليًا داخل `.superdesign/blood-events/single-blood-group-{390,768,1440}.png` ولا تدخل Git. helper الفترات يضيف بيانات فقط في منشأة اصطناعية مميزة، ويتحقق من عدم تعديلها بواسطة الحفظ.
