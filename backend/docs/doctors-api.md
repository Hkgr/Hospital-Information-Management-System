# إدارة الأطباء

الأطباء سجلات في `staff`، والتخصصات عبر `staff_specialties`. لا يوجد جدول doctors أو إنشاء حساب دخول عند إضافة طبيب. Laravel مسؤول عن البيانات والتقارير وSanctum والصلاحيات الديناميكية؛ Next.js يعرضها عبر proxy محدد. FastAPI خارج هذا المسار.

## الصلاحيات والنطاق

`staff` دليل مهني عالمي. القراءة تعرض الكود والاسم والتوصيف والنوع والتخصصات والترخيص والهاتف والحالة والنسخة فقط، مع أعداد وارتباطات تخص المنشأة المختارة. لا تُصدَّر بيانات التمويل أو حسابات الدخول أو أسماء المرضى.

كل مسار يتطلب `auth:sanctum → account.active → abilities:api` و`doctors.view` في المنشأة الفعالة المحددة. جميع الردود، بما فيها الأخطاء والملفات، تحمل `Cache-Control: private, no-store` و`Vary: Authorization`.

| التفويض | مصدره | الاستخدام |
| --- | --- | --- |
| doctors.view | facility_user_roles → roles → role_permissions → permissions | قراءة الدليل والأعداد والخيارات داخل المنشأة |
| doctors.link | المسار نفسه داخل المنشأة | إضافات وإزالات ارتباطات عيادات المنشأة فقط |
| doctors.export | المسار نفسه داخل المنشأة | تقارير القائمة والتفاصيل |
| doctors.directory.create | global_user_roles → roles → role_permissions → permissions | إضافة سجل مهني عالمي |
| doctors.directory.update | المسار العالمي نفسه | تعديل بيانات الطبيب أو تعطيله عالميًا |
| doctors.directory.delete | المسار العالمي نفسه | حذف سجل غير مرتبط بأي مرجع أو تاريخ |

أنشأت migration الجديدة `2026_09_12_000001_add_doctor_directory_and_global_role_assignments.php` الربط العالمي الصريح؛ لا تكفي صلاحية في facility_user_roles لإدارة الدليل، ولا يمنح اسم `super_admin` أي تجاوز. تُقرأ الأدوار والصلاحيات الفعالة في كل عملية. النطاق العالمي الجديد مستخدم حاليًا لصلاحيات الدليل الثلاث فقط؛ لا يحوّل الصلاحيات الطبية الأخرى إلى صلاحيات عالمية. تظل إدارة ارتباطات العيادة القائمة خاضعة لصلاحيات clinics الحالية، دون منحها تعديل بيانات الطبيب عالميًا.

تعريفات `DoctorPermissionsSeeder` قابلة للإعادة، ولا تمنح أدوارًا ولا تعيد تفعيل تعريف معطل. خطوات الإسناد الصريح إلى `testadmin` ودور `super_admin` في [دليل النشر](deployment.md).

## المسارات والعقود

أرسل `Authorization: Bearer <token>` بقدرة `api`. بادئة المسارات `/api/doctors`، و`facility_id` مطلوب في كل طلب؛ يرفض الخادم منشأة غير مخولة بـ403، ولا يجمع صلاحيات منشأتين.

| الطريقة والمسار | تفويض إضافي | الرد |
| --- | --- | --- |
| GET `/` | — | `{data: Doctor[], meta: {page,per_page,total,last_page}}` |
| POST `/` | directory.create، وlink عند إرسال ارتباطات | 201 `{data: Doctor}` |
| GET `/options` | — | `{data: {staff_types,specialties,doctor_types_configured,capabilities}}` |
| GET `/options/clinics` | — | خيارات العيادات الفعالة مع بحث وترقيم وحالة الربط عند doctor_id |
| GET `/{doctor}` | — | `{data: Doctor}` |
| PUT `/{doctor}` | directory.update، وlink عند إرسال تغييرات ارتباط | `{data: Doctor}` |
| DELETE `/{doctor}` | directory.delete | 204، أو409 عند وجود مراجع |
| POST `/{doctor}/deactivate` | directory.update | تعطيل عالمي منفصل، `{data: Doctor}` |
| GET `/{doctor}/clinics` | — | ارتباطات حالية مميزة مع بحث وترقيم |
| PUT `/{doctor}/clinics` | link | تغييرات ارتباط فقط، `{data: Doctor}` |
| GET `/export/{xlsx\|pdf}` | export | جميع النتائج المطابقة، ملف ثنائي |
| GET `/{doctor}/report` | export | PDF تفاصيل كامل ضمن المنشأة |

إضافة طبيب دون عيادات:

```json
{
  "facility_id": 1,
  "code": "0001",
  "name": "طبيب تجريبي",
  "description": "توصيف مهني",
  "staff_type_id": 1,
  "specialty_ids": [1],
  "license_no": null,
  "phone": null,
  "is_active": true,
  "clinic_add_ids": []
}
```

المعرّفات في المثال توضيحية؛ تُقرأ الخيارات الفعلية من API. الكود مطلوب ≤40 وفريد عالميًا في staff؛ الاسم ≤200، التوصيف ≤10000، الترخيص ≤60، الهاتف ≤30. `specialty_ids` قائمة مطلوبة، تحتوي تخصصًا واحدًا على الأقل عند توفر تخصصات فعالة. يسمح التعديل بالإبقاء على تخصص أو نوع قائم معطل، ولا يسمح بإضافته إلى طبيب جديد. لا تُغيّر الحقول غير المعروضة مثل funding_source_id.

يضيف PUT رقم `lock_version` الحالي وقائمتي `clinic_add_ids` و`clinic_remove_ids` الصريحتين (≤200 لكل منهما). مسار `/{doctor}/clinics` يقبل المنشأة والنسخة والقائمتين فقط؛ الحقول المهنية محظورة فيه. الحذف والتعطيل يستقبلان المنشأة والنسخة فقط. الإضافة تحتاج طبيبًا وعيادات فعالة، داخل المنشأة المخولة نفسها.

`Doctor` يحتوي: id، code، name، description، staff_type `{id,code,name_ar}`، specialties `[{id,name_ar,is_active}]`، license_no، phone، is_active، lock_version، clinic_count، patient_count، clinics_preview (حتى3)، patient_count_definition. رابط العيادة يرد كـ`{id,code,name_ar,starts_on,is_linked,can_view}`؛ ظهور رابط تفاصيلها يحتاج `clinics.view`.

`capabilities` هي create/update/delete/link/export/view_clinics الحالية، وتستخدم الواجهة هذه النتيجة لإظهار الإجراءات. ليست صلاحيات مخزنة داخل التوكن، ولا تعفي الخادم من التحقق.

القائمة تدعم search≤200 (الكود/الاسم/التوصيف أو اسم العيادة الحالية الفعالة وكودها ضمن المنشأة)، status=active|inactive، specialty_id، clinic_id، sort=code|name|clinic_count|patient_count|is_active، direction=asc|desc، page≥1، per_page=1..100 (افتراضي20). الترتيب الثانوي id ثابت. تستخدم LIKE؛ الرمزان `%` و`_` نمطا بحث وليسا SQL. القيمة `0` بحث صالح. لا يقتصر التصدير على الصفحة المعروضة، والأعمدة التسعة المسموحة هي number/code/name/specialties/description/clinics/clinic_count/patient_count/is_active.

## الأنواع والأعداد والتزامن

استعادة التعارض تستخدم `/options/clinics` مع `ids[]` الثابتة: حتى100 معرّف في الطلب مع تفريدها، وبحد أقصى أربع دفعات لضم200 إضافة و200 إزالة. يعاد الكود والاسم الحاليان وحالة الارتباط، و`unavailable` بأسباب عامة آمنة للخيارات غير المتاحة. لا يجتمع ids مع البحث أو الترقيم، وتبقى الاستجابة داخل المنشأة المخولة. يعاد فحص نسخة الطبيب بعد اكتمال الجلب ثم يختار المستخدم التعديلات ويحفظ صراحةً. العقد المشترك والمسار المناظر للعيادات موثقان في [directory-review.md](directory-review.md).

`CLINIC_DOCTOR_STAFF_TYPES` أكواد `staff_types.code` المعتمدة فعليًا، مفصولة بفواصل، وهو المصدر نفسه لوحدة العيادات. القيمة الفارغة تعيد دليلًا وخيارات فارغة وتفسيرًا في الواجهة وتمنع الإنشاء؛ لا تخمين باسم عربي أو ID. الإضافة واختيار ارتباط جديد يتطلبان نوعًا فعالًا وطبيبًا فعالًا. لا يخفي عرض الدليل سجلًا قائمًا لمجرد تعطيله، ما دام نوعه ضمن الأكواد المعتمدة.

`DoctorCounts` يعزل المؤشرات:

- عدد العيادات: distinct للعيادات الفعالة ذات ارتباط حالي في المنشأة المختارة، بفترة `[starts_on, ends_on)` حسب يوم منطقتها الزمنية. تعريف واحد للقائمة والنافذة والتقرير.
- عدد المرضى: distinct visits.patient_id للزيارات `complete` وغير الملغاة حيث `attending_staff_id` للطبيب والمنشأة مطابقة. لا يُحسب من عياداته أو الطبيب المقيم أو الوصفات والإجراءات. لا تُرسل هوية المريض.

`ClinicStaffLinks` هي خدمة الكتابة المشتركة من الطرفين. ترتيب الأقفال داخل transaction: staff بترتيب id، ثم clinics بترتيب id، ثم فترات الزوج. لا يُطلب قفل staff جديد بعد قفل clinic. يُحدَّث رقم نسخة الطرفين عند تغيير الارتباط فعليًا، مع التدقيق في transaction نفسها وإعادة محاولة deadlock ثلاث مرات. أي كاتب مستقبلي يجب أن يتبع السياسة نفسها.

الإزالة تنهي الفترة عند اليوم ولا تحذفها. إعادة الإضافة في اليوم نفسه تفتح سجل اليوم نفسه، ويحفظ التدقيق كل انتقال. لا تُستبدل المجموعة ولا تُحذف ارتباطات مخفية أو تخص منشأة أخرى. يرفض التداخل مع فترة مستقبلية أو فترات متكررة بـ409. حفظ نسخة قديمة من أي طرف يرفض بـDOCTOR_VERSION_CONFLICT أو CLINIC_VERSION_CONFLICT. تحتفظ الواجهة بالمسودة، وتجلب لقطة حديثة وتتحقق من نسختها، ثم تطلب اختيار الحقول والارتباطات صراحةً قبل حفظ مستقل؛ لا دمج تلقائي.

الحذف يفحص مراجع staff الحالية والتاريخية، وتمنع مفاتيح RESTRICT أي مرجع إضافي أو سباق. لا cascade للسجلات الطبية. ارتباط بحساب أو زيارة أو تشخيص أو وصفة أو تاريخ عيادة يمنع الحذف بـ409؛ التعطيل العالمي إجراء مستقل للمخوّل به. تُدقّق عمليات الدليل والروابط والتصدير بمعرّف طلب من الخادم.

## التقارير والأخطاء

قالب `DirectoryReport` و`reports.directory` مشترك للوحدتين. PDF يستخدم **Cairo Regular وBold ثابتين TTF** مسجلين حصريًا في mPDF، مع OTL للعربية، وتعطيل fallback والتحميل الخارجي. مصدر الخط والترخيص والتحقق في [fonts/cairo](../resources/fonts/cairo/README.md). ترويسة أولى بشعار132px وعنوان21pt وشبكة إصدار، ثم ترويسة استمرار مختصرة وتذييل مرقّم. التفاصيل رأسية، والقائمة أفقية لأكثر من أربعة أعمدة، وبيانات الجدول10.5pt دون تصغير شامل. يبقى التوصيف المعتدل في الجدول؛ النص الطويل بحسب عرضه والتفافه يحيل إلى ملحق كامل باسم السجل وكوده. التفاصيل تعرض بطاقة وشبكة حقول وأعداد ثم التوصيف والارتباطات.

XLSX يحدد **اسم Cairo ولا يضمّن الخط**؛ يلزم تثبيته على جهاز العرض. اتجاه RTL، شعار وبيانات إصدار من الخادم، رؤوس وفلاتر وتجميدA9، نصوص صريحة تحفظ الأصفار وتمنع formula injection، وأعداد رقمية. يحتفظ بالقيمة الكاملة في الخلية ضمن حد32767 وحدةUTF-16؛ النص الأطول من ارتفاع الصف العملي يظهر بمقتطف معلّم مع نسخة كاملة في «النصوص للطباعة». تجاوز حد الخلية يحفظ أجزاء كاملة مرتبة في «بيانات النصوص» بدل فقدها. لا دمج في صفوف البيانات، والارتفاع يتبع النص. الطباعة تلائم العرض لصفحة والارتفاع غير مقيد، مع تكرار الرؤوس. تفاصيل السلوك والمعاينة الفعلية والعينات المطابقة قبل/بعد في [مراجعة التقارير](directory-review.md).

الحدود الحالية:1000 سجل و5000 ارتباط حالي؛ تجاوزها422 EXPORT_LIMIT_EXCEEDED دون قطع النتائج. تصدر أرقام `DR-{facility}-{year}-{sequence}` و`CL-…` من number_sequences تحت قفل، واسم المُصدر من المستخدم المصادق، والوقت من منطقة المنشأة. الفلاتر بأسماء مفهومة. الملفات في الذاكرة، وتعود attachment مع X-Report-Number؛ لا روابط عامة أو أسماء مرضى. قد توجد فجوات في التسلسل عند فشل التصدير.

الأخطاء:401 UNAUTHENTICATED؛403 ACCOUNT_INACTIVE (إلغاء التوكنات) / MISSING_API_ABILITY / DOCTOR_ACCESS_DENIED / DOCTOR_DIRECTORY_ACCESS_DENIED؛404 DOCTOR_NOT_FOUND؛409 DOCTOR_VERSION_CONFLICT / CLINIC_PERIOD_CONFLICT / DOCTOR_REFERENCED؛422 validation أو حدود التصدير؛500 DOCTORS_UNAVAILABLE. يُبلّغ الخطأ الداخلي مرة واحدة عبر Laravel دون كشف SQL أو رسالة الاستثناء. Scramble `/docs/api` و`/docs/api.json` يوثق المخططات والتحقق والأخطاء والملفات الثنائية.

## التحقق

استخدم MySQL اختبارية فقط وبعد `php artisan test-db:check --connect --env=testing`. اختبارات Feature تغطي نطاقين لمنشأتين، فصل التفويض العالمي، CRUD والأنواع والتخصصات، حفظ الحقول الأخرى، الاتجاهين والتاريخ والتعارض، الزيارات المكررة والمسودة والملغاة وطبيب آخر، المراجع، N+1، الخصوصية والحقن والتقارير وOpenAPI.

نتائج التنفيذ الفعلية، المسار HTTP الحي، الصور والعينات وحدود التحقق في [توثيق الواجهة](../../frontend/docs/doctors.md). إدارة المرضى والحسابات والتخصصات والأنواع ومنح الصلاحيات عبر واجهة، والتصدير المؤجل، خارج النطاق.


تحسين الأداء والربط: راجع [قياسات الدليل والتحقق](directory-performance.md). يصبح doctor_types_configured=false عند غياب أي كود نوع فعال مطابق للإعداد؛ لا تكفي قائمة أكواد غير موجودة أو غير فعالة. البحث المتبادل يستخدم الارتباطات الحالية فقط ولا يكرر سجلات القائمة.
