# تشخيصات إضافية وملاحظة تشخيص الزيارة

يضيف `VisitDiagnosisAdditionsSeeder` الأسماء التسعة عشر المعتمدة في قائمته فقط إذا غاب الاسم نفسه بعد إزالة الفراغات الطرفية. لا يصحح الأسماء طبيًا ولا يطابق الاسم العام بدل الأكثر تحديدًا. يستخدم مولّد الأكواد الحالي `IssuedCodes::diagnosis()` وقفل إنشاء دليل التشخيصات نفسه؛ لا معرّفات ثابتة ولا أكواد ICD أو تصنيفات مستنتجة.

السجل الموجود، مثل «متلازمة غلانزمان» بالكود `DOS-DX-95` في الملف المرجعي، يبقى بمعرّفه وكوده وجميع بياناته. لا تتغير حالة السجلات المعطلة ولا تُنشأ نسخة فعالة بديلة عنها. إعادة تشغيل الإضافة لا تكرر السجلات أو تستهلك أكواد إضافية للأسماء الموجودة. ملف SQL مرجع فقط، ولا يُستورد.

بعد تحديث التطبيق، ينفّذ المشغّل من مجلد `backend`:

```bash
php artisan db:seed --class=VisitDiagnosisAdditionsSeeder --force
```

هذا هو Seeder الإضافة المحدد؛ لا يلزم تشغيل `DatabaseSeeder` العام أو أي SQL يدوي. لا migration أو تغيير مخطط أو صلاحيات جديدة. تحقّق من الأسماء في قائمة اختيار تشخيص الزيارة، باستخدام حساب مخوّل أصلًا. إذا كان تعريف موجود معطلًا، تُراجع حالته إداريًا ولا يعاد تفعيله ضمن هذه الإضافة.

بعد اختيار التشخيص، يظهر حقل «ملاحظة التشخيص» الاختياري، بمثال «مثل: ناكس، نقائلي، أو تفاصيل إضافية». الملاحظة نص بحد أقصى 10000 محرف وتخص `visit_diagnoses.note` للزيارة نفسها؛ ليست وصفًا في دليل `diagnoses`.

تُرسل ضمن `diagnoses[*].note` في مسار حفظ الزيارة الحالي، وتُعاد في بيانات التحرير والقراءة. يحدّث النص المرسل الملاحظة، ويزيلها `null` أو الحقل الفارغ في النموذج. غياب المفتاح في طلب عميل قديم يحافظ على الملاحظة الموجودة. تظهر أسفل التشخيص في تفاصيل الزيارة، وفي مراجعة البيانات المحفوظة والتعارض. تبقى الصلاحيات ونسخ السجلات والمعاملة وإعادة الطلب والتدقيق الحاليون كما هم.

يشمل التحقق اختبارات Laravel على قاعدة MySQL/MariaDB اختبارية معزولة بعد حاجز الأمان، وحالات الإضافة المتكررة والتعريف الموجود والمعطل والملاحظة الاختيارية وحفظها وتعديلها ومسحها والعزل ورفض غير المخوّل. اختبار `frontend/tests/diagnosis-notes-live.test.mjs` يستخدم Next ثم Laravel ثم MariaDB الحقيقيين، ويتحقق من خيارات الأسماء وإعادة فتح الملاحظة وعرضها وتعديلها ومسحها بعد تحديث الصفحة؛ لا يعترض API ولا يحاكي استجاباته. تُسجل نتائج التشغيل الفعلية في PR.

يلزم إعادة بناء Next بالطريقة المعتادة بعد تحديث الواجهة. لا تغيير للتقارير أو استيراد Excel أو FastAPI أو وحدات أخرى، ولا تنفيذ لهذه الأوامر على الإنتاج ضمن المهمة.
