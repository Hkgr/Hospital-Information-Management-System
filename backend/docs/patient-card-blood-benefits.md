# استفادة الدم من بطاقة المريض

تُخفى وجهة «بنك الدم» من التنقل المشترك، ودرج الهاتف، واختصارات الرئيسية ودليل المهام لجميع الأدوار. تبقى المسارات الداخلية وواجهات بنك الدم وصلاحياتها الحالية؛ إخفاء التنقل ليس إلغاءً للتفويض.

## التسجيل

داخل زيارة مسودة، في «الخدمات والإجراءات»، يفتح اختيار الخدمة ذات الكود `SER-4-001` نموذج `EventEditor` الحالي. لا يُستخدم اسم الخدمة للمطابقة ولا يُثبّت معرّفها الرقمي. هوية المريض للعرض فقط ومأخوذة من البطاقة والزيارة المعتمدتين في الخادم.

النموذج يحافظ على التمييز الصريح بين صرف مكوّن ونقل دم فعلي، والكمية بالكيلوغرام، والزمرة، والمكوّن، والطبيب المرتبط بعيادته، والفحوص الاختيارية وشروط النقل. تاريخ الواقعة وعيادتها وطبيبها يطابقون خدمة الزيارة. لا تُنشأ قيم طبية أو فترة تقارير أو حركة مخزون افتراضية. منطق بنك الدم الحالي لا ينشئ حركة مخزون عند حفظ الاستفادة.

زر «اعتماد الاستفادة في المسودة» يجهّز المسودة فقط. احفظ قسم الخدمات لإتمام التسجيل: يُحفظ سجل الخدمة والاستفادة وهوية بنك الدم المرتبطة بالمريض عند الحاجة ضمن معاملة واحدة باستخدام الكاتب الحالي. فتح النافذة أو إلغاؤها لا يكتب أي واقعة؛ تبقى مدخلات النافذة مؤقتًا لإعادة فتحها ومسودات الخدمات الأخرى محفوظة. لا يمكن حفظ خدمة نقل دم جديدة بلا بيانات استفادة صالحة.

عند تبديل خدمة نقل دم غير محفوظة إلى خدمة عادية، تُلغى بيانات الاستفادة لذلك السطر وذاكرة نموذجها المؤقتة تمامًا، مع إبقاء الملاحظة وبقية المسودات وإعادة إظهار اختيار العيادة والطبيب المعتاد. العودة إلى نقل الدم تفتح نموذجًا جديدًا؛ لا تستعيد بيانات أُلغيَت. لا ينطبق ذلك على استفادة محفوظة؛ يظل استبدال خدمتها ممنوعًا.

صلاحية العملية هي `dossiers.services.update` مع متطلبات قراءة البطاقة والزيارة الحالية (`dossiers.medical.view` و`dossiers.visits.view`) في المشفى. يغطي ذلك دور `data_entry` الحالي دون Seeder أو منح جديد؛ لا يمنح إدارة بنك الدم أو بحث المرضى العام أو تعديل المخزون أو إنشاء دليل. كل حفظ يعيد التحقق من التفويض والسياق في Laravel؛ لا تُقبل هوية مريض/منشأة/زيارة بديلة داخل حمولة الاستفادة.

تستخدم العملية `request_id` ونسخة الزيارة والخدمة والاستفادة، ومعاملة وسجل تدقيق الكاتبَين الحاليين. إعادة نفس الطلب تعيد نفس النتيجة، وتغيير محتواه بنفس المفتاح يُرفض. يمكن تسجيل عملية أخرى مشروعة بطلب جديد. يظل ربط الصرف بالنقل لذات الشخص والمكوّن فريدًا ويحتسب استفادة واحدة وفق بنك الدم الحالي.

تُستعاد الاستفادة المرتبطة نفسها عند تعديل الخدمة وتُعرض مرجعيتها ونوعها وكميتها في البطاقة. تعارض النسخ يحتاج جلب الأحدث ومراجعة صريحة؛ لا تُنشأ واقعة بديلة. تُمنع إزالة الخدمة المرتبطة أو استبدالها من هذا المسار برسالة واضحة، ولا تُحذف الاستفادة أو تُلغى تلقائيًا. كذلك لا يُغيّر تاريخ الزيارة بصمت مع بقاء واقعة دم بتاريخ مختلف. الزيارات المكتملة للقراءة فقط.

الخدمات القديمة غير المرتبطة تبقى كما هي، دون إنشاء استفادات بأثر رجعي. إذا كانت للمريض بيانات دم تاريخية لم تُوحّد بعد، يتوقف الحفظ برسالة `BLOOD_BANK_RECONCILIATION_REQUIRED`؛ لا ينفّذ هذا الإصلاح تهيئة أو ربطًا تاريخيًا تلقائيًا.

## حذف البطاقة والاستيراد

يطبّق حذف البطاقة المصرح به سياسة الحذف الحالية ضمن المعاملة نفسها. تُراجع روابط الدم تحت الأقفال قبل تغيير أي جزء من البطاقة؛ ثم تُزال خدماتها التابعة، وأسماء أكواد استفاداتها وفحوصها، والنقل المرتبط بها وإجراءاته التابعة بترتيب يحترم المفاتيح الأجنبية. تُحذف مرحلتا الصرف والنقل معًا فقط إذا كانتا تابعتين للبطاقة نفسها. تبقى هوية بنك الدم ووقائعه المستقلة والصرف السابق خارج البطاقة وجميع بيانات المنشآت الأخرى محفوظة. يبقى تدقيق وقائع الدم محفوظًا أيضًا. إذا كان صرف تابع للبطاقة مرتبطًا بنقل خارجها، يُرفض حذف البطاقة برسالة تعارض 409 قبل أي حذف، دون فصل الرابط أو حذف النقل الخارجي.

قالب Excel الحالي لا يحمل بيانات الاستفادة؛ لذلك تُرفض الخدمة `SER-4-001` في **المعاينة** برسالة تتضمن `Services` ورقم الصف الفعلي وكود الخدمة وتوجّه إلى تسجيلها من البطاقة. تُعاد مراجعة تعريف الخدمة تحت القفل عند الاعتماد، فلا تُكتب مجموعة المريض جزئيًا إذا تغير التعريف منذ المعاينة. لا تُنشأ استفادة افتراضية ولا يُتخطّى صف الخدمة. استيراد الخدمات العادية وإعادة طلبها يبقيان على عقدهما الحالي. يتضمن تنزيل القالب هذا التنبيه؛ لا تغيير لأعمدته أو إصداره.

## العقد

- `GET /api/dossiers/{dossier}/visits/{visit}/blood-benefit-context?facility_id=…`: هوية المريض المختصرة وخيارات النموذج الفعالة؛ بلا كتابة.
- `GET /api/dossiers/{dossier}/visits/{visit}/blood-benefit-issues?facility_id=…`: صرف سابق متاح لهذا المريض فقط، مع البحث والترقيم.
- الحفظ عبر `PUT /api/dossiers/{dossier}/visits/{visit}/clinical` الموجود، بإضافة `services[*].blood_benefit`. حقول الاستفادة هي عقد بنك الدم الحالي دون هوية قابلة للتغيير؛ `id` و`lock_version` مطلوبان عند تعديل الاستفادة المرتبطة.
- الاستجابة الحالية تضيف `blood_bank_event_id` و`blood_benefit` لسجل الخدمة. الحماية الحالية Sanctum/الحساب الفعال/قدرة `api` و`private, no-store` مستمرة. أخطاء التحقق داخل `services.N.blood_benefit.*` تُعرض عند إعادة فتح النموذج، والمسودة لا تضيع.

## النشر والترحيل

الترحيل الإضافي الوحيد:

`2026_10_21_000001_link_visit_service_blood_benefit.php`

يضيف رابطًا nullable وفريدًا إلى `visit_services` مع مفتاح أجنبي مركّب يتحقق من المنشأة، ويترك جميع الصفوف القديمة بلا رابط. عند النقل الفعلي تُحفظ أيضًا علاقة `blood_transfusions.visit_id` الموجودة، مع المريض نفسه. لا تعديل لمخططات قديمة ولا تعبئة تاريخية ولا Seeder ولا SQL يدوي ولا أمر تحويل بيانات.

بعد النسخة الاحتياطية المعتادة ومراجعة إصدار التطبيق، أوامر المشغّل من جذر المشروع. طبّق المخطط قبل تحويل المرور إلى إصدار Laravel الجديد:

```bash
git pull --ff-only
cd backend
composer install --no-dev --prefer-dist --optimize-autoloader
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan route:cache
php artisan view:cache
cd ../frontend
npm ci
# اضبط LARAVEL_API_URL بعنوان Laravel الداخلي المعتمد قبل البناء.
npm run build
```

أعد تشغيل خدمة Next بالطريقة المعتمدة في النشر، مع نسخ `public` و`.next/static` إلى standalone إن كان النشر يستخدمه. إعادة البناء لازمة للتحويلين المحددين الجديدين. لا تُنفّذ هذه الأوامر من هذا PR على الإنتاج.

التراجع عن migration يرفض حذف العمود إذا وُجدت روابط محفوظة، بدل فقد العلاقة الطبية. عند التراجع البرمجي أبقِ المخطط الإضافي؛ لا تحذف الوقائع أو الروابط لتجاوز الحاجز.

## التحقق

التحقق محلي فقط على MySQL driver / MariaDB 10.11.18، قاعدة `blood_bank_cities_testing` على `127.0.0.1:13416` بعد `test-db:check --connect`. طُبّق الترحيل الإضافي على القاعدة المأهولة دون fresh أو refresh أو إعادة تهيئة. اختبارات Laravel تعمل بحدود معاملات عبر bootstrap الحفظ الموجود؛ لا تعيد إنشاء المخطط.

اختبار الانحدار قبل الإصلاح: الخادم أعاد 200 لخدمة جديدة بلا استفادة بدل 422. بعده يغطي `DossierBloodBenefitTest` الربط والحفظ الذري وإعادة الطلب والتعديل والصلاحيات والتلاعب والبيانات القديمة والصرف المرتبط وحاجز التراجع.

`frontend/tests/card-blood-benefit-live.test.mjs` يشغّل Chrome ضد بناء Next standalone جديد ثم Laravel الحقيقي وقاعدة الاختبار، دون اعتراض API أو استجابات محاكية. يشمل 390 و768 و1440px، التحقق والإلغاء وبقاء المسودة والحفظ وإعادة الطلب وإعادة الفتح والتعديل ورفض الوصول. اللقطات ببيانات اصطناعية فقط.

نتيجة التنفيذ الأولية قبل تصحيحات المراجعة: اختبارات الربط الثمانية نجحت (92 assertion)، واختبارات المتصفح الثلاثة نجحت في تشغيل واحد، واختبارا التنقل وسبعة اختبارات مسودات الوصفات نجحوا. المجموعات الأوسع آنذاك: 63 اختبارًا / 3067 assertions؛ 62 ناجحة وفشل سابق واحد موضح أدناه، دون skips. نتائج تصحيحات المراجعة النهائية موثقة في وصف PR؛ لم يُشغّل كامل المستودع أو تحقق على قاعدة المشفى.

تصحيح مراجعة PR #73 لا يضيف migration أو Seeder أو تحويل بيانات جديدًا؛ يلزم فقط الترحيل الإضافي الأصلي أعلاه إن لم يُنفّذ بعد، وإعادة بناء Next وتشغيل النسخة المصححة. لا تغييرات في الصلاحيات أو التمويل أو مخزون الدم أو FastAPI.

تُسجّل النتائج النهائية وحدود الفحص في وصف PR. فشل قائم ومؤكد أيضًا بالكاتب الأصلي من develop: `BloodEventsTest::test_event_doctor_eligibility_uses_occurrence_date_and_retained_links_are_historical` يعيد 200 بدل 422 عند نقل تاريخ واقعة قديمة خارج فترة الطبيب مع بقاء الطبيب والعيادة نفسيهما. لم يُغيّر هذا الإصلاح قواعد التعديل العامة لمعالجة ذلك الفشل المنفصل؛ المسار الجديد يقيّد التاريخ بالزيارة ويحمي تغيير تاريخها.

أظهرت إعادة تشغيل `DossierImportTest` كاملة أيضًا ثلاثة إخفاقات سابقة تخص حفظ الرقم الورقي للمريض الجديد، وليست خدمة نقل الدم: `test_import_audit_api_exposes_allowlisted_provenance_and_separate_identity_assignments` و`test_new_patient_validation_issues_no_code_and_commit_preserves_source_identifiers` و`test_failure_after_personal_write_rolls_back_the_bundle_and_does_not_reserve_its_paper_number`. تأكد تكرارها بتحميل `ImportBundle` من الرأس السابق `661a3a49`، بما فيه تحذير معالجات الأخطاء في الاختبار الأخير. تبقى منفصلة وخارج نطاق هذه المراجعة؛ لا تُسجّل المجموعات الأوسع باعتبارها ناجحة بالكامل.
