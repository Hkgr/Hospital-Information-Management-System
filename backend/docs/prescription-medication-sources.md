# مصدر الدواء وتمويل الوصفات

## السبب والعقد النهائي

كان «مصدر الدواء العام» قائمة أكواد ثابتة في الواجهة والتحقق وقيود قاعدة البيانات، بينما كانت الوصفات تقرأ جدول `funding_sources` المستقل عن تلك القائمة؛ لذلك كان خلو الجدول يمنع اختيار التمويل. وكان التمويل مطلوبًا للنوع المرتبط بالجرعة فقط.

أصبح جدول `funding_sources` الموجود هو المرجع الوحيد للقائمتين، دون جدول موازٍ. تعيد خيارات البطاقة وخيارات تمويل الوصفات الصفوف الفعالة نفسها وبالمعرّفات والترتيب نفسيهما؛ الإضافة وتعديل الاسم والتعطيل تنعكس عليهما. المرجع عالمي حاليًا، وليس له `facility_id`؛ تبقى قراءة الخيارات وحفظ الوقائع خاضعتين لصلاحية البطاقة والمنشأة. لا يمنح هذا الإصلاح صلاحية إنشاء تعريفات لمدخل البيانات.

يختار المستخدم المصدر صراحة لكل وصفة جديدة، سواء كانت غير مرتبطة أو مرتبطة بجرعة أو غير متوفرة. لا قيمة افتراضية ولا استنتاج من الدواء. تحفظ الوصفة `funding_source_id` الموجود. يحتفظ API مصدر الدواء العام بحقل `medication_source` ذي قيمة الكود للتوافق؛ تستخدم القائمة معرّف الصف نفسه، ويحوّله المحرر إلى الكود عند إرسال العقد القائم. تعيد القراءة أيضًا `medication_source_id` و`medication_source_name`.

تعرض الوصفة القديمة بلا مصدر «غير محدد»، ويتطلب تعديلها اختيار مصدر فعال. يبقى المصدر المعطل المحفوظ ظاهرًا تاريخيًا؛ يمكن إبقاؤه عند تصحيح الوصفة نفسها، ولا يمكن اختياره لوصفة جديدة أو تغييره إليه. لا تُملأ مصادر الوصفات القديمة تلقائيًا. إلغاء وصفة تاريخية لا يتطلب اختلاق مصدر لها. تغيرت التسميات الظاهرة إلى «وصفات»؛ أسماء الجداول والمسارات ورموز الأخطاء القائمة محفوظة، والفواتير المالية خارج النطاق.

## الترحيل والبيانات القائمة

الترحيل الإضافي المطلوب:

`2026_10_15_000001_unify_prescription_medication_sources.php`

- يقرأ التعريفات الخمسة المعتمدة سابقًا في مصدر الدواء العام من `database/data/medication-sources.json` لتهيئة المرجع الأولية فقط؛ خيارات التشغيل لا تقرأ هذا الملف.
- يضيف الناقص فقط، ويحافظ على معرّفات الصفوف الموجودة وأسمائها المعدّلة وحالات تعطيلها. لا ينسخ المصادر إلى جدول آخر ولا يغيّر علاقات الوصفات القديمة.
- يتوقف قبل الإضافة أو تعديل المخطط عند مطابقة ملتبسة، بما فيها تطابق الاسم مع كود مختلف. تظهر المعرّفات والأكواد للمراجعة؛ لا مطابقة تخمينية ولا دمج آلي.
- يبدّل قيود الأكواد الخمسة بمفاتيح خارجية إلى `funding_sources.code` في `patient_dossiers` و`oncology_session_doses` و`dose_session_items` و`visit_medications`. تتسع حقول المصدر إلى 50 محرفًا لتوافق المرجع. هذا ضروري حتى تعمل خيارات المصدر الجديدة في المسارات التي تستخدم مصدر الدواء العام نفسه.
- تعديلات الاسم والنشاط متاحة وفق الآلية القائمة؛ الأكواد المشار إليها ثابتة، ويحميها المفتاح الخارجي من التغيير والحذف.
- يسمح قيد أنواع الوصفات بتمويل الأنواع الثلاثة؛ الإلزام والتحقق من النشاط داخل معاملة الحفظ، مع بقاء NULL التاريخي قابلًا للقراءة.

التراجع محافظ: يرفض قبل أي DDL إذا استُخدم مصدر خارج الأكواد القديمة أو كانت علاقات التمويل لا يجيزها القيد القديم. لا يحذف وصفات أو مصادر ولا يصفر علاقات لتمرير التراجع. عند الرفض، يلزم إصلاح إصدار التطبيق إلى الأمام أو مراجعة تشغيلية منفصلة؛ لا تحاول تجاوز الحاجز.

## أوامر الإصدار للمشغّل

لم تُنفّذ هذه الأوامر على الإنتاج. بعد النسخ الاحتياطي المعتمد ونشر ملفات الإصدار، من `backend`:

```bash
# معاينة فقط، دون --apply: راجع أي التباس قبل نافذة الترقية.
php artisan dossiers:setup-prescription-funding

php artisan down --retry=60
php artisan migrate --path=database/migrations/2026_10_15_000001_unify_prescription_medication_sources.php --force
php artisan optimize:clear
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

يلزم تشغيل migration أعلاه. **لا يلزم أمر مستقل لترحيل البيانات أو Seeder أو SQL أو منح صلاحيات**: الترحيل نفسه يهيئ التعريفات المعتمدة الناقصة. الأمر السابق للمعاينة، وليس شرطًا لتشغيل `--apply`؛ لا تعالج الالتباس بإعادة تسمية صفوف تاريخية عشوائيًا.

من `frontend`، مع إعداد `LARAVEL_API_URL` الصحيح قبل البناء:

```bash
npm ci
npm run build
```

انشر ناتج standalone مع `public` و`.next/static` وفق إجراء المشروع الحالي، وأعد تشغيل عملية Next وعمال PHP بالطريقة المعتمدة لدى المشغّل، ثم:

```bash
# من backend، بعد اكتمال تشغيل الإصدارين المتوافقين.
php artisan up
```

لا يوجد اسم خدمة تشغيل موحّد في المستودع لإعطاء أمر restart خاص بخادم المشفى. لا تشغّل إصدار الواجهة الجديد مع مخطط الوصفات القديم. بعد الإصدار، تحقق بحساب مصرح من تطابق خيارات القائمتين، ومن حفظ مصدر صريح وإعادة قراءة الوصفة؛ لا تستخدم بيانات حقيقية لاختبار عشوائي.

## التحقق المحلي

الاختبارات على MariaDB محلية معزولة بعد `test-db:check --connect --env=testing`، دون إعادة تهيئة قاعدة مأهولة. يغطي `PrescriptionMedicationSourcesTest` تطابق المراجع والتعديل والتعطيل، إلزام المصدر للأنواع الثلاثة ورفض القيم غير الصالحة دون كتابة، حفظ المصدر وتغييره، NULL التاريخي، المصدر المعطل والتقارير PDF/XLSX. يغطي اختبار المتصفح الحقيقي مسار مدخل البيانات عبر Next ثم Laravel ثم MariaDB، مع مقارنة معرّفات القائمتين وحفظ أنواع الوصفات الثلاثة، وحالات فشل الخيارات وخلوها.

يفحص `tests/Support/verify-prescription-source-migration.php` الترقية والتراجع على قاعدة اختبارية مأهولة: تطابق بيانات التاريخ ومعرّفاته، ورفض تراجع غير آمن، ورفض التباس المرجع قبل الكتابة. ليس أمر تشغيل للإنتاج، ولا يقوم بتهيئة قاعدة جديدة أو إعادة ضبطها.
