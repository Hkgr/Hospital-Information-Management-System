# دورة حياة الأطباء والعيادات

هذا التغيير مبني على develop بعد دمج PR #10، ويحافظ على تعديلات الربط والأداء والتصدير فيه.

## التشخيص والسياسة

الحذف كان يرفض `clinic_staff` حتى عندما لا توجد مراجع طبية، دون بديل للأرشفة. التعطيل كان ينجح مع المراجع ويحفظ الفترات؛ لم يكن له سبب الفشل نفسه. كان ينقصه إجراء إعادة التفعيل، وكانت إضافة الأطباء من مسار تعديل العيادة تقبل عيادة غير فعالة. فحص حذف العيادة لم يكن يصنّف `report_metric_catalog_items.clinic_id`، مع بقاء حماية المفتاح الأجنبي.

| الإجراء | النتيجة | الصلاحية |
| --- | --- | --- |
| حذف نهائي | فقط دون مراجع أو فترات ارتباط؛ يحذف تخصصات الطبيب الذاتية معه، دون أي سجل طبي أو طرف مقابل | delete |
| أرشفة وإزالة من الدليل | يحفظ السجل والمراجع والفترات، ويجعله غير فعال ومؤرشفًا | delete |
| تعطيل مؤقت | يغير النشاط فقط، دون تغيير تواريخ الارتباط | update |
| إعادة تفعيل | سجل غير فعال وغير مؤرشف؛ يلزم نوع طبي فعال ومعتمد للطبيب | update |
| استعادة | يمحو علامة الأرشفة ويُبقي السجل غير فعال؛ التفعيل قرار مستقل | update |

للأطباء، الصلاحيات السابقة تعني `doctors.directory.*` بتفويض عالمي صريح، إضافة إلى `doctors.view` في المنشأة. صلاحية الربط أو دور على مستوى المنشأة لا يمنحها. للعيادات تعني `clinics.*` في المنشأة نفسها. لم تُضف صلاحيات أو منح جديدة. أرشفة الطبيب عالمية؛ لا تؤرشف العيادات ولا تمس حساب المستخدم المرتبط به.

الأرشفة تغلق الفترة السارية عند تاريخ اليوم في المنطقة الزمنية لمنشأتها. تلغي الفترة المستقبلية بجعل `ends_on = starts_on`، دون حذف صفها. الفترات المنتهية لا تتغير. الاستعادة وإعادة التفعيل لا تفتحان أي فترة. العدادات والروابط الحالية وخيارات الإسناد تتطلب طرفين فعالين غير مؤرشفين ونوع طبي معتمد وفترة نصف مفتوحة `[starts_on, ends_on)`. عدادات المرضى والمراجع الطبية التاريخية لا تُحذف ولا تتغير تعريفاتها.

## API

تحت `/api/doctors/{doctor}` و`/api/clinics/{clinic}`:

- `GET /deletion-preview?facility_id=...`: `{data:{action:"delete"|"archive",organizational_links,has_other_references,lock_version,archived}}`. عدد الفترات يخص المنشأة المصرح بها فقط. لا يعرض أسماء مرضى أو تفاصيل منشآت أخرى؛ وجود مرجع خارجها قد يمنع الحذف العالمي دون عرض تفاصيله.
- `DELETE`: يبقى `204` للحذف النهائي فقط. وجود مرجع يعيد `409 *_REFERENCED` مع بديل الأرشفة؛ لا تتحول العملية تلقائيًا إلى أرشفة.
- `POST /archive`, `/restore`, `/reactivate`, `/deactivate`: جسم `{facility_id,lock_version}`، واستجابة `200 {data:record}` تشمل `archived_at` و`is_active` والنسخة والعدادات الحالية. الأرشفة لا تعيد استجابة حذف نهائي.
- `GET /link-history?facility_id=...&page=1&per_page=20`: فترات مسموح باستعراضها بصلاحية view الحالية؛ `{data:[{id,code,name,starts_on,ends_on}],meta}`. يشمل المؤرشف والمعطل والمنتهي والمجدول؛ لا يعرض بيانات مرضى أو منشآت أخرى.
- القائمة تستبعد المؤرشف افتراضيًا، وتدعمه صراحة عبر `status=archived`. `active` و`inactive` يستبعدانه. التفاصيل والتقرير المفرد يظلان متاحين بالصلاحيات الحالية. التصدير الشامل يطبق الفلتر نفسه.

Sanctum والحساب الفعال وقدرة `api` و`private, no-store` تبقى مطبقة. أخطاء الحالة المتكررة `409 *_STATE_CONFLICT`، والنسخة القديمة `409 *_VERSION_CONFLICT`. النوع الطبي غير القابل للتفعيل يعيد `422` برسالة حقل مفهومة. إزالة كود النوع من إعداد دليل الأطباء تخفي سجلات ذلك النوع وفق حد الدليل السابق؛ يعالج المسؤول الإعداد قبل إدارتها.

## الاتساق والواجهة

الفحص النهائي والحذف/الأرشفة والتدقيق داخل transaction؛ المعاينة ليست ضمانًا. المفاتيح الأجنبية التقييدية تبقى فعالة وتمنع حذف مرجع وصل بالتزامن. ترتيب الأقفال: staff مرتبة، ثم clinics مرتبة، ثم الفترات. أرشفة العيادة تكتشف الأطباء قبل القفل وتعيد التحقق بقراءة مقفلة؛ عضوية جديدة غير مقفلة تسبب تعارضًا بدل قلب ترتيب الأقفال. الفترات المعدلة تُدقّق في الاتجاهين وتزيد نسخة الطرف المقابل مرة واحدة. ملخص المراجع مصنّف مركزيًا، واختبار يطابقه مع المفاتيح الأجنبية الفعلية.

النافذة تجلب أهلية الحذف قبل إتاحة التأكيد، وتبقي الأرشفة والتعطيل والاستعادة والتفعيل قرارات صريحة. نسخة المعاينة المختلفة أو تعارض العملية يستلزمان إغلاقًا وتحديثًا قبل إعادة التأكيد. لا يوجد حفظ أو أرشفة تلقائيان. تمنع النافذة الإرسال المكرر، وتُلغي طلباتها عند زوال سياقها. فشل غير حاسم أثناء الكتابة يستلزم تحديث الحالة قبل المحاولة مجددًا. نجاح العملية يحدث revision؛ جاهزية التصدير تبقى مرتبطة بنجاح طلب القائمة الجديد وفق إصلاح PR #10.

## Migration والاختبار

`2026_09_12_000003_add_directory_archived_at.php` تضيف `archived_at` قابلًا لـnull ومفهرسًا إلى `staff` و`clinics`. لا تعديل لمهاجرات مطبقة أو قيود الحذف، ولا إعداد جديد. يلزم تطبيق migration بالطريقة المعتادة قبل تشغيل النسخة الجديدة؛ هذه المهمة لا تنشرها.

الاختبارات تستخدم MySQL اختبارية معزولة فقط. `Tests\TestCase` يطبق حاجز `TestDatabaseSafety` قبل traits المهاجرات. اختبارات HTTP تستخدم `RefreshDatabase`، واختبار التزامن يستخدم `DatabaseMigrations` واتصال PHP مستقل ببيئة testing ليراقب حظر الحذف أثناء transaction تضيف مرجعًا. لا تستخدم قاعدة تطوير/إنتاج أو SQLite. rollback يزيل علامتي الأرشفة فقط؛ لا يستعيد فترات أغلقتها الأرشفة، لذا ليس بديلًا لإجراء استعادة سجل.

اختبارات المتصفح تستخدم Chrome وخادم Next محليًا واستجابات API محاكية؛ لا تُعد اختبارًا حيًا للواجهة والخادم معًا. اختبارات الخادم تشغّل HTTP kernel وMySQL فعليًا. نتائج التشغيل النهائية مدونة نصيًا في PR، دون صور أو ملفات تقارير.
