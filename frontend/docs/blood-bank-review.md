# مراجعة بنك الدم

## سجل الشخص والوقائع الموحد

التنفيذ الأحدث على `feature/blood-bank-unified-events`، انطلاقًا من develop بعد دمج PR #17. راجع [توزيع الحقول وخطة الترحيل](../../backend/docs/blood-bank-unified-events.md). `EventScreen` يعرض السجل افتراضيًا وصفحتي الشخص والواقعة، ويستخدم `DirectoryTable`, `DirectoryRowActions`, `DirectoryBack`, `Pagination`, `Modal` والحقول والـPicker وInlineDoctor الموجودة. أزيل النموذجان القديمان غير المستخدمين، دون تغيير AppShell أو تصميم الأطباء والعيادات.

نموذج الواقعة يبدأ باختيار شخص أو إضافته، ثم بيانات الحدث، والعيادة والطبيب، والفحوص الاختيارية. الاستفادة تحدد الصرف أو النقل الفعلي؛ النقل يحدد الارتباط بالصرف صراحةً. الكمية فارغة ابتداءً ومطلوبة بالكيلوغرام؛ تعديل التاريخي يبقي وحدته. يراجع المستخدم أحدث نسخة ومسودته صراحةً بعد التعارض.

الاختبارات الحية الجديدة في `tests/blood-bank-live.test.mjs` و`tests/blood-bank-reports-live.test.mjs` تستخدم Laravel وMariaDB الحقيقية عبر Next standalone. جهّز قاعدة اختبار معزولة ومتغيرات حاجز الأمان أولًا، ثم ابنِ Next مع `LARAVEL_API_URL` لخادم Laravel الاختباري. بعد **كل** build، أنشئ `.next/standalone/public` و`.next/standalone/.next/static` وانسخ محتويات `public` و`.next/static` إليهما قبل بدء `node .next/standalone/server.js`؛ تشغيل standalone قبل النسخ قد يترك الأصول غير متاحة حتى إعادة تشغيله. اضبط `TEST_BASE_URL` على loopback و`PLAYWRIGHT_BROWSERS_PATH` لمسار المتصفح المثبت محليًا، ثم شغّل:

```sh
node --test --test-concurrency=1 tests/blood-bank-live.test.mjs tests/blood-bank-reports-live.test.mjs
```

لا تشغّل اختبارات RefreshDatabase بالتزامن مع الخوادم الحية على القاعدة نفسها. تحتوي بعض الحالات حقن انقطاع/تأخير في النقل فوق الاستجابات الحقيقية لاختبار الاستعادة، ولا تستبدل الحفظ بمحاكاة API. يوجد اختبار مستقل باتصالَي PHP متزامنين داخل الكاتب الفعلي. بيانات الدخول والتوكنات والعينات واللقطات تبقى محلية داخل المسارات المستثناة من Git؛ يلغي cleanup توكنات الاختبار المملوكة له.

اللقطات الجديدة والعينات في `frontend/.superdesign/blood-events/`: السجل والشخص والواقعة ونموذج التبرع عند 390 و768 و1440، ونموذج النقل المرتبط، وتقارير ledger/person/donation/issue/transfusion بصيغتي PDF وXLSX. نتائج التشغيل النهائية موثقة في مستند Backend المرتبط أعلاه. السجل العريض يستخدم تمرير المكوّن المشترك على الهاتف، دون تمرير أفقي للصفحة.

## إصلاح نماذج التسجيل بعد PR #15

فرع الإصلاح `fix/blood-bank-profile-workflows` مبني على develop عند `14c301a`؛ PR #15 كان مدمجًا. يعيد استخدام `Modal`, `Picker`, أنماط حقول العيادات و`sectionHeading` و`doctorChoice`، مع تعديل CSS محدود داخل نموذج بنك الدم لضبط radio؛ لا تعديل لـAppShell أو الأطباء والعيادات.

المجموعات: البيانات الشخصية، العنوان، بيانات الدم، العيادة والطبيب، الفحوصات. المحافظات السورية تأتي من Laravel؛ البحث داخل خيارات الدليل، والمدن تُجلب حسب المحافظة وتُلغى عند تبديلها. يحتفظ النموذج بمعرّفات الاختيار والنص اليدوي في حقول منفصلة ويُرسل المسار النشط فقط. عنوان المريض المرتبط للقراءة دون نسخه إلى مسودة الإدخال المباشر. تظهر القيم التاريخية غير الموجودة في الخيارات الحالية دون تحويلها.

الفحوص لا تُضاف تلقائيًا؛ زر إضافة فحص يعرض اختيار النوع ثم الحالة فقط. يُمنع التكرار ويمكن إزالة الصف غير المحفوظ. الصف التاريخي يحتفظ بهويته ونتيجته وطريقته؛ يرسل النموذج الحالة فقط. يمكن حفظ «مكتمل» دون نتيجة. اختيار الطبيب لم يعد يعيد تحميل قائمته؛ تغيير العيادة ما زال يلغي الطلب ويمسح الطبيب السابق وحده.

### إثبات الانحدار والنتائج الجديدة

- قبل الإصلاح، اختبارا Laravel رفضا القائمة الفارغة وتحديث فحص واحد بـ422 بسبب required/size:3. محاولة الاختبار الأولى أخطأت باستخدام actingAs مع مسارات تتطلب Bearer حقيقيًا؛ صُحح تجهيز الاختبار ثم ثبت فشل العقد نفسه، وليس المصادقة.
- عند إعادة استعلام الأطباء السابق مؤقتًا لاختبار الانحدار، فشل الإجمالي: 26 بدل طبيب فريد واحد. استُعيد الإصلاح بعد الاختبار، ونجح الاختبار ضمن مجموعة Laravel الجديدة.
- اختبار المتصفح على standalone السابق فشل لأن زر «إضافة فحص» غير موجود. على البناء الجديد نجح حفظ العنوان والفحص الاختياري لكلا النوعين عبر Next → Laravel → MySQL وإعادة قراءة القيم المحفوظة.
- `BloodBankProfileWorkflowTest|BloodBankTest|BloodBankMigrationConcurrencyTest`: 14 اختبارًا ناجحًا، 1363 تحققًا. تشمل الترحيل والـrollback مع نتائج/طرق قديمة، تثبيت هوية الدليل عند إعادة seeder، منع خلط العناوين، الصلاحيات والعزل والتعارض وإعادة الطلب والتصحيحات المتزامنة لأكواد التبرع.
- التكامل والمتصفح على البناء النهائي: 13 حالة ناجحة معًا؛ ثم اختبار مستقل ناجح لإفراغ تهيئة أنواع الأطباء واستعادتها عبر الخادم الاختباري الحقيقي. حقن التأخير/الفشل يستخدم الاستجابة الفعلية، وليس API محاكية. لا تعد هذه الحالات محاكاة بديلة عن التكامل؛ الحفظ والقراءة يعبران Next وLaravel وMySQL.
- القاعدة المستخدمة `mysql` / `hospital_testing` / `127.0.0.1:13306` بعد حاجز الأمان. لا إنتاج ولا SQLite. لا تُشغّل اختبارات RefreshDatabase أثناء وجود بيانات الاختبار الحي.
- إعادة تحقق Laravel النهائية بعد Pint: 13 اختبارًا و1348 تحققًا ناجحًا؛ اختبار migration/التزامن المنفصل الناجح يضيف اختبارًا و15 تحققًا. Pint --dirty --test وgit diff --check وroute:list لبنك الدم (14 مسارًا محميًا) نجحت.
- TypeScript وlint وproduction build نجحت. تعذر بناء واحد بسبب EBUSY عندما كانت عملية Next الاختبارية تقفل standalone؛ أُوقفت العملية وأُعيد البناء بنجاح. صُحح كذلك مسار إخراج لقطات Windows وأُعيد التقاطها داخل المشروع.

### نتيجة فحص الأطباء وحدود الاستنتاج

قورنت `/hospital-api/blood-bank/doctors` مع `/hospital-api/clinics/{id}/doctors` وظهرت الهوية نفسها فعليًا، واختيرت من النموذج قبل تعديل الاستعلام. عند وجود أنواع معتمدة لم يتكرر اختفاء جميع الأطباء. بعد ملاحظة غياب CLINIC_DOCTOR_STAFF_TYPES في ملف .env المحلي (قُرئت هذه القيمة فقط دون اتصال بقاعدته)، أُعيد غياب الإعداد عمدًا داخل خادم الاختبار: اختفى الطبيب من بنك الدم والعيادات معًا، وظهرت رسالة التهيئة الجديدة، ثم عاد بعد استعادة النوع الاصطناعي المعتمد. هذا سبب مثبت في الاختبار، لكنه لا يثبت إعداد الخادم الفعلي؛ قد تزوّد البيئة أو config cache قيمة تختلف عن الملف. لم يُعدَّل ملف .env أو إعداد الإنتاج ولا يُخمن أي نوع طبي. كلا القسمين يشترط النوع الطبي المعتمد والنشاط والفترة السارية والمنشأة. يُعرض عدم تهيئة أنواع الأطباء برسالة واضحة بدل تقديمه كخيارات فارغة. أصلح التجميع تضخم إجمالي الخيارات عند تكرار روابط حالية للهوية نفسها؛ هذا عيب قابل للاختبار مستقل عن إثبات سبب اختفاء جميع الأسماء لدى المستخدم.

### اللقطات المحلية

Chrome / Playwright مع Cairo المحلي. المسار المتجاهل من Git `frontend/.superdesign/blood-bank-review/workflow-{person,address,blood,screenings}-{donor,recipient}-{390,1440}.png`. تمت المعاينة الفعلية وضبط أحجام radio بعد اكتشاف تأثرها بتنسيق مدخلات النص. الصفحة والحوار بلا تمدد أفقي؛ النموذج الطويل يتمرر داخل الحوار مع أزرار الحفظ الثابتة. اللقطات والبيانات الاصطناعية والتوكنات لا تدخل Git.

يستخدم القسم `DirectoryTable`, `DirectoryRowActions`, `DirectoryBack`, `Pagination`, `Modal` وملف CSS نفسه المستخدم في الأطباء والعيادات. لم يُعَد تصميم AppShell؛ الإضافة فيه رابط بنك الدم حسب الصلاحية وعنوان الصفحات فقط. Cairo وأصول الهوية محلية.

اختيار المنشأة يعيد استخدام `directoryFacility` مع `blood_bank.view`. البحث يستخدم `useClinicSearch` نفسه؛ أُضيف prefix اختياري لبحث جدول التبرعات كي يحفظ `donation_search/page/per_page` دون تغيير بحث قائمة الأشخاص أو سرقة التركيز بعد debounce. القيم الافتراضية للأطباء والعيادات لم تتغير.

النماذج تحتفظ بالمسودات محليًا حتى الإغلاق أو تغيير المنشأة/الجلسة، ولا تخزّن بيانات الأشخاص في localStorage. مسودة المريض المختار مستقلة عن مسودة الإدخال المباشر؛ البيانات المرتبطة تُقرأ من Laravel ولا تُنسخ إلى ملف المستفيد. الطبيب يُنشأ بالمكوّن ومسار الربط الحاليين. عند فشل تحديث الخيارات بعد نجاح الإنشاء يحتفظ النموذج بمعرّفه ويتيح إعادة جلب الخيارات أو استكمال الارتباط، دون POST جديد.

التعارض يحفظ المسودة، ثم يعرض أحدث نسخة والمقارنة واختيار الحقول صراحة. جلب أحدث نسخة يحدّث القائمة/التفاصيل أيضًا، ولا يحفظ تلقائيًا. تغيير تاريخ التبرع يظهر كوده الجديد بعد الحفظ؛ الكود السابق يبقى صالحًا للبحث عن الواقعة نفسها.

## نتائج التنفيذ الأصلي (PR #15)

- Laravel + MySQL `hospital_testing` على `127.0.0.1:13306` بعد `test-db:check --connect --env=testing`؛ لا SQLite ولا إنتاج.
- `BloodBankTest`: 7 اختبارات، 1118 تحققًا، بما فيها عقد OpenAPI الفعلي لكل مسارات القراءة ومساري بيانات المستفيد.
- `BloodBankMigrationConcurrencyTest`: اختبار واحد، 13 تحققًا؛ rollback/backfill وحفظ كل بيانات التبرع القديمة، وتصحيحان متداخلان فعليًا بعمليتي PHP منفصلتين؛ الثاني 409.
- مجموعة `BloodBankTest|ClinicApiTest|DoctorApiTest|DirectoryLifecycleTest` الأولى: 59 اختبارًا، 2184 تحققًا. أُعيدت اختبارات بنك الدم الموسعة كما سبق؛ اختبارات الأقسام الحالية الـ54 بقيت ناجحة.
- اختبارات متصفح الأطباء والعيادات: 40 ناجحة؛ أُعيدت 11 حالة بحث/تاريخ/منشأة بعد إضافة prefix الاختياري ونجحت.
- `blood-bank-live.test.mjs`: 7 اختبارات ناجحة، تشمل إنشاء تبرع من النموذج والرجوع إلى بحث الكود السابق بعد اعتماده؛ مرور حقيقي من Next standalone إلى Laravel إلى MySQL، مع تحقق من البيانات المحفوظة وعدم تغير أعداد الزيارات والنقل والخدمات والإجراءات. حالتا الأعطال تحقنان فشل/تأخير الشبكة فوق الاستجابات الحقيقية، وتُذكران كذلك في أسماء الاختبارات؛ لا تُحسبان بديلًا عن المرور الحقيقي.
- TypeScript، lint، production build، Pint و`git diff --check` نجحت. 14 مسار بنك دم محمي وواجهتا Swagger/JSON ظهرت في route:list.

أثناء التجهيز فشلت محاولات قبل اكتمال نسخ أصول standalone وقبل جاهزية الخادم، ومحاولة اختارت المنشأة الاصطناعية الثانية بسبب ترتيب أكواد البيانات التجريبية. عولج تجهيز الخادم والبيانات وأُعيدت الاختبارات؛ لم يُعدّل منطق اختيار المنشأة لتجاوزها. لا تُحسب تلك المحاولات كنجاح.

## المعاينة المحلية

Chrome بواسطة Playwright؛ لقطات فعلية ببيانات اصطناعية عند 390 و768 و1440، في `frontend/.superdesign/blood-bank-review` المتجاهل من Git. تشمل القوائم وملفي المتبرع والمستفيد والنماذج والفحوص وواقعة التبرع وكودها. جداول الهاتف تحتفظ بالتمرير داخل الجدول؛ الصفحة نفسها لا تمتد أفقيًا. النماذج الطويلة تتمرر داخل الحوار وتستخدم أزرار الحفظ الحالية. لا تغيير في تصميم Login أو الأقسام السابقة.

لا توجد لقطات أو بيانات اختبار سرية داخل Git. لا يُمثل هذا اختبار نشر أو اعتمادًا طبيًا للتبرعات؛ القبول والمخزون والنقل خارج النطاق.
