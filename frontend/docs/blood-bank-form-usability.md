# سهولة استخدام نماذج بنك الدم — استكمال PR #19

هذا التحديث يكمل تنسيق النماذج فوق إصلاح الفترات والزمرة في `62a7d0706686cf55987c3bb0b0609a08ec665b75`. لا تغييرات في backend أو migrations أو FastAPI أو المصادقة أو AppShell.

## المرجع والتغييرات

فُحص `DoctorEditor` و`ClinicEditor` و`Modal` و`clinics.module.css`. المرجع المشترك الحالي هو الحوار الأصلي ذو العنوان الثابت وجسم مستقل للتمرير وشريط الإجراءات المثبت، وشبكة الحقول وعناوين الأقسام المرقّمة وأزرار primary/secondary وPagination. أعيد استخدامها مباشرة، دون تغيير تصميم الأطباء أو العيادات. تقتصر الإضافات البصرية على `profile.module.css` داخل بنك الدم.

- أربعة أقسام واضحة: الشخص، الواقعة، العيادة والطبيب، الفحوص. مسافات مستقلة بين الأقسام والحقول، وتسميات بمحاذاة بداية السطر مع RTL.
- أسماء الشخص في صفوف مترابطة، والميلاد ودقته والجنس في صف واحد للشاشات الواسعة، ثم التواصل والسكن. المحافظة تشغل العرض عند غياب المدينة؛ وعند الاختيار تظهر المحافظة والمدينة جنبًا إلى جنب حيث يتسع العرض. يتحول التوزيع إلى عمود على الهاتف.
- ملخص الشخص الموجود يبرز الاسم والكود والزمرة الحالية والهاتف ورابط هوية المريض إن وجد. تفاصيل المريض المقروءة فقط متاحة في disclosure بدل تمديد النموذج تلقائيًا بكل حقوله.
- قوائم الاختيار صفوف واضحة ذات علامة تحديد وكود، وتمرير محصور داخل القائمة مع ترقيم خارجي. يظل الاختيار بلوحة المفاتيح ممكنًا. الأدلة المحلية الكثيرة تستخدم عمودين عند اتساع الشاشة.
- أزرار الحفظ والإلغاء هي أزرار الدليل المشتركة، مع حالة حفظ معلنة وسبب واضح لتعطيل الحفظ عند نقص اختيار الشخص/العيادة/الطبيب. الإجراءات الثانوية منفصلة عن الحفظ، وحوار إضافة الطبيب الأصلي يحفظ المسودة ويعيد التركيز إلى فاتحه.
- عند 422 ترتبط رسائل الخادم بالحقول باستخدام أسمائها، بما فيها حقول `person.*` وعمليات الاختيار. توضع `aria-invalid` و`aria-describedby`، ثم ينتقل التركيز إلى أول حقل خاطئ حسب ترتيب النموذج بعد رفع حالة busy ويُمرّر إلى وسط الجزء المرئي. أخطاء required الأصلية تستخدم ترتيب المتصفح مع تصحيح التمرير. عند غياب حقل قابل للتركيز تنتقل القراءة إلى رسالة الخطأ. لا مسح للمسودة ولا إعادة حفظ تلقائي.

لم يتغير عقد الطلب أو صلاحية أو UUID أو lock_version أو رابط الصرف بالنقل. تظل زمرة واحدة للواقعة، مع استقلال الشخص الموجود وحماية الردود المتأخرة. تُحفظ كميات kg والوحدات التاريخية بدلالاتها؛ الفحوص اختيارية بحالة فقط.

## المقارنة المرئية

[معرض قبل/بعد كامل على GitHub](reviews/pr-19/README.md) يشمل ست حالات عند 390 و768 و1440px: شخص جديد وتبرع، شخص موجود وتبرع، شخص جديد وصرف، نقل مرتبط بصرف، مريض مسجل وصرف، وتعديل ملف الشخص. الصور أجزاء تمرير فعلية من رأس الحوار حتى نهايته، وحالات رفض التاريخ المستقبلي. لم يُعدّل CSS أو ارتفاع الحوار لأجل اللقطة. روجعت الصور فعليًا، بما فيها التنسيق والتركيز ووضوح الحفظ والإلغاء وعدم التمرير الأفقي.

الصورة ليست بديلًا عن الاختبار: `blood-bank-form-usability.test.mjs` يغطي التركيز وإتاحة الحقل فوق الأزرار المثبتة، ورسائل اسمَي الشخص وترتيبهما، وبقاء الهاتف والكمية والمسودات، وتعديل ملف الشخص، والتمرير الداخلي والاختيار باللوحة وإغلاق حوار الطبيب وإعادة التركيز. `blood-bank-form-review.mjs` يعيد التقاط الحالات من التطبيق الفعلي ويتحقق من التركيز عند أخطاء الوقائع في صور «بعد».

## بيئة التحقق

Next 16.3.4 standalone جديد على `127.0.0.1:3194` → Laravel الاختباري `127.0.0.1:8194` → MariaDB 10.11.18، driver=mysql، قاعدة `blood_bank_cities_testing` على `127.0.0.1:13416`. اجتاز الاتصال حاجز TestDatabaseSafety. لا SQLite أو بيانات إنتاج. اختبارات HTTP تُشغّل بالتتابع، واختبارات RefreshDatabase منفصلة زمنيًا عنها.

```sh
# backend: بعد تحميل متغيرات MySQL الاختبارية المعتمدة فقط
php artisan test-db:check --connect --env=testing
php artisan test --env=testing --filter=BloodEventsTest
./vendor/bin/pint --dirty --test

# frontend: LARAVEL_API_URL للخادم الاختباري عند البناء
npm run build
npx tsc --noEmit
npm run lint
# انسخ public و.next/static إلى standalone وشغّل البناء الجديد قبل الآتي:
node --test --test-concurrency=1 tests/blood-bank-form-usability.test.mjs tests/blood-bank-periods-live.test.mjs tests/blood-bank-live.test.mjs tests/blood-bank-reports-live.test.mjs
node tests/blood-bank-form-review.mjs after
git diff --check
```

اختبار التركيز فشل فعليًا قبل الإصلاح: ظل التركيز خارج حقل التاريخ بعد 422. اختبارات هذا التحديث تستعمل استجابات Laravel الفعلية، دون page.route أو استجابة API محاكية؛ حالات تأخير الشبكة القديمة تبقى لاختبار سباق الردود فقط. لا تغيير أو إعادة اختبار واسع لمكونات الأقسام غير المعدّلة لمجرد مطابقة CSS.
