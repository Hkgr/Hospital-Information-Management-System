# الخدمات والإجراءات: سياق المشفى واتساق الدليل

بدأ الإصلاح من `develop` عند `78d18d8` على `fix/catalog-workflows-and-consistency`، لأن PR #12 مدمج بالفعل. هذا إصلاح لاحق مستقل وفق الشرط الوارد في المهمة، وليس تحديثًا لفرع مدمج.

## المرجع التنفيذي

استُخرجت `DirectoryTable` و`DirectoryRowActions` و`DirectoryBack` من التنفيذ الحالي للأطباء والعيادات، ثم استُخدمت في الأقسام الثلاثة. بقي DOM المرجعين وCSS الخاص بهما كما هو؛ لم يتغير AppShell أو Login أو Cairo المحلي.

المرجع الفعلي الأحدث يستخدم أزرار الأيقونات بهذا الترتيب: استعراض، تعديل، حذف، ثم إجراء الحالة. **لا توجد قائمة إجراءات منسدلة مشتركة في المرجعين الحاليين**؛ لذلك اتُّبع نمطهما الموجود بدل اختراع قائمة موازية. تستخدم الخدمات والإجراءات أيضًا `LifecycleActions` و`Modal` و`ColumnMenu` و`LongText` و`Pagination` المشتركة. الأرشفة المستقلة الإضافية تبقى وفق صلاحية الحذف العالمية، حتى دون صلاحية تعديل، مع تأكيد أثرها على الدليل المشترك.

رؤوس الجدول وخلفياته والتحويم والحدود والمسافات والخط والترويسات وأزرار البحث والتصدير والترقيم وأحجام الصفحات `10/20/50/100` تأتي من الأنماط نفسها. اختلاف أعمدة البيانات وعدد الأزرار يعكس طبيعة السجل والصلاحيات. تحافظ خلايا الكود والنوع في قائمة الخدمات على سطر واحد لتجنب تجزئة الكود والشارة، ويظل التمرير داخل الجدول. لا توجد صور أو خطوط خارجية أو مكتبات جديدة.

في التفاصيل: زر الرجوع ثم العنوان وأزرار التعديل والحالة والتقرير في مواضع المرجع، وبطاقة الوصف والحقائق، ثم جدول «المرضى المستفيدون وتواريخ التقديم» باستخدام `DirectoryTable`. لا تظهر أقسام السجل والارتباطات السابقة في العرض الرئيسي؛ بقي التدقيق وتاريخه في الخادم.

## السلوك الوظيفي

- يُحلّ سياق المشفى في Laravel عبر `CATALOG_FACILITY_CODE`؛ تعرض الواجهة اسم المشفى فقط. لا معرّف ثابتًا داخل React ولا اختيارًا لأول منشأة. رابط منشأة مختلفة يُرفض ولا يوسع الوصول.
- زر «إضافة فئة» بجانب حقل الفئة يعيد استخدام الحوار نفسه. الإلغاء والرمز المكرر لا يمسحان مسودة الخدمة. تُحدَّث الخيارات وتُختار الفئة الجديدة الفعالة تلقائيًا. الفئة غير الفعالة تُحفظ ولكن لا تصلح لاختيار خدمة جديدة. الحقول تستخدم أسماء وصول ثابتة ورسائل أخطاء مرتبطة بها، ويعود التركيز إلى الزر بعد الإغلاق.
- كل صف في جدول التفاصيل واقعة تقديم، بمفتاح `source:event_id` وتاريخ الحدث نفسه، مع كود المريض واسمه ورقم الزيارة إن وجد. البحث والتاريخ والترتيب والترقيم من الخادم؛ العدّان هما المرضى الفريدون ومرات التقديم من كامل النتائج المطابقة.
- تبقى النتائج السابقة أثناء التحديث ضمن السياق نفسه فقط. تُلغى الطلبات القديمة، ولا يعيد رد متأخر بيانات سجل أُغلق أو مرشح تجاوزه المستخدم. دون صلاحية المستفيدين تظهر رسالة ولا تُطلب الأسماء والأكواد.
- بقيت عقود الحفظ و`lock_version` ومراجعة التعارض الصريحة وجاهزية التصدير مرتبطة بنجاح الطلب الحالي. التصدير يشمل جميع النتائج المطابقة والأعمدة المختارة، وليس الصفحة الحالية.

## التحقق القابل للتكرار

راجع [توثيق الخادم](../../backend/docs/services-procedures.md) لإعداد المشفى والصلاحيات وحاجز MySQL. لا تشغّل اختبارات `RefreshDatabase` بالتزامن مع الاختبار الحي.

```powershell
# backend، بعد ضبط .env.testing المحلية واجتياز الحاجز
php artisan test-db:check --connect --env=testing
php artisan test --env=testing --filter='Catalog(Api|Workflow)Test|DirectoryReportViewTest'
$env:APP_ENV='testing'
php -S 127.0.0.1:8015 tests/Support/directory-routing-server.php

# frontend، في نافذة أخرى
$env:LARAVEL_API_URL='http://127.0.0.1:8015/api'
npm.cmd run build
Copy-Item -LiteralPath public -Destination .next/standalone -Recurse -Force
Copy-Item -LiteralPath .next/static -Destination .next/standalone/.next -Recurse -Force
$env:PORT='3105'; $env:HOSTNAME='127.0.0.1'
node .next/standalone/server.js

# frontend، في نافذة ثالثة
npm.cmd run test:catalog
npm.cmd run test:catalog-live
$env:TEST_BASE_URL='http://127.0.0.1:3105'; $env:PLAYWRIGHT_CHANNEL='chrome'
node --test tests/clinics.test.mjs tests/doctors.test.mjs
```

الخادم الاختباري فقط يقرأ رمز المنشأة الاصطناعية من الملف المؤقت المحمي بعد فحص MySQL. لا تُستخدم هذه الآلية في التطبيق المنشور. تُلغى توكنات التشغيل الحي ويُحذف ملفها عند النهاية.

صور المقارنة الحقيقية تُنشأ محليًا في `.superdesign/catalog-consistency-review/`: قوائم الأطباء والعيادات والخدمات والإجراءات وصفحاتها المنفردة عند `390` و`1440px` (16 صورة). تستخدم Chrome المثبت عبر Playwright، مع استجابات Laravel الفعلية وMySQL. تُثبَّت نهاية الحركة أثناء التصوير، ويُفحص عدم تداخل العنوان والمحتوى مع القائمة الجانبية. الصور وبيانات التشغيل محلية مهملة في Git.

## نتائج الإصلاح

- MySQL `hospital_testing` على `127.0.0.1:13306`، driver `mysql`؛ اجتاز حاجز الأمان والاتصال.
- Laravel: 14 اختبارًا ناجحًا، 1016 تحققًا، تشمل OpenAPI والتفويض والفئات والوقائع والإحصاءات والتقارير القائمة.
- واجهة الخدمات: 14 اختبارًا ناجحًا، تشمل الحوارات والصلاحيات والتعارضات والطلبات المتأخرة والتصدير واستعادة URL و390/768/1440px.
- الأطباء والعيادات: 40 اختبارًا ناجحًا بعد استخراج المكوّنات المشتركة.
- التكامل الحي: 7 اختبارات ناجحة دون `page.route`؛ CRUD والأرشفة والاستعادة للنوعين، إنشاء الفئة من الواجهة، تكرار الوقائع وتواريخها، البحث والتاريخ والترقيم والإجماليات، الرفض بالصلاحيات والمقارنة البصرية.
- TypeScript وlint وproduction build وPint و`git diff --check`: نجاح.

ظهر أثناء التطوير فشل في اختبار الفئة بسبب تغيّر اسم وصول حقل الرمز مع رسالة الخطأ؛ صُحّح الحقل وأعيد الاختبار بنجاح. صُحّحت أيضًا توقعات اختبارات الأزرار لتناسب المكوّنات المشتركة الفعلية. هذه النتائج تخص النسخة المصححة؛ لم يُدعَ نجاح الاختبارات قبل الإصلاح.

لا migration أو صلاحية جديدة. يلزم ضبط `CATALOG_FACILITY_CODE` إلى الرمز الحقيقي للمشفى قبل استخدام القسم في بيئة تشغيل؛ تُرفض الواجهة بوضوح إذا غاب الإعداد. لم يُفحص أو يُعدّل الإنتاج، ولم تتغير FastAPI أو شروط `visits.status = complete` أو تعريف المستفيدين.
