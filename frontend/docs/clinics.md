# واجهة إدارة العيادات

تحديث PR #9 يستخدم معرّف الطبيب الثابت ودفعات100 عند استعادة التعارض، ويعرض الاسم والكود الحاليين دون إسقاط الاختيار بسبب إعادة التسمية. [توثيق الإصلاح المشترك والتقارير الجديدة ونتائجها](../../backend/docs/directory-review.md).

`/clinics` و`/clinics/[id]` داخل AuthenticatedLayout الحالي، بخط Cairo المحلي وإطار AppShell نفسه. يظهر رابط العيادات لمن لديه clinics.view في منشأة واحدة على الأقل، ورابط [الأطباء](doctors.md) حسب doctors.view. صلاحية الواجهة لا تحل محل تحقق Laravel في كل عملية.

تحديث وحدة الأطباء وحّد أدوات الأعمدة والترقيم والنص الطويل ومراجعة التعارض وقالب الجداول والنوافذ للوحدتين. أُضيف تنظيم واضح للعناوين وشريط الأدوات ومجموعات الحقول، وأزرار حفظ ثابتة داخل النافذة. بقي سلوك التعارض وتاريخ البحث أدناه محفوظًا. العينات الحالية تستخدم Cairo في PDF وExcel، وتشمل صور768px أيضًا. نتائج التحقق والصور الحديثة في [توثيق الأطباء](doctors.md)؛ الجداول التاريخية أدناه تصف نتائج PR إنشاء العيادات وإصلاحه فقط.

القائمة تعرض رقمًا متتابعًا عبر الصفحات وكودًا يفتح التفاصيل، واسمًا وحالة وتوصيفًا مختصرًا وأسماء أطباء وعددين وإجراءات حسب الصلاحيات. الأطباء والأعداد تُحمّل من الخادم. البحث والفلاتر والترتيب والترقيم تحفظ في query string، والعودة من التفاصيل تبقيها. اختيار منشأة واحدة تلقائي، وأكثر من منشأة عبر اختيار مسموح.

البحث مؤخر 300ms، والطلبات السابقة تُلغى. كل نتيجة مرتبطة بمفتاح طلبها؛ لا يظهر سياق سابق أثناء بدء الطلب التالي. تغير المستخدم يعيد تركيب شجرة المصادقة الموجودة. التصدير يرسل الفلاتر والأعمدة المرئية إلى Laravel ليولد جميع النتائج، ولا يصنع تقريرًا من صفوف الصفحة الحالية.

النوافذ native dialog مع حصر التركيز وEscape وإعادته إلى الزر السابق، ومنع الإغلاق والإرسال المكرر أثناء الحفظ. أخطاء التحقق تظهر بجوار الحقول، والمدخلات تبقى بعد الفشل. اختيار الطبيب يرسل إضافات وإزالات صريحة؛ الخيارات غير المحملة أو المخفية لا تُسقط ارتباطاتها.

على الهاتف التمرير الأفقي محصور في الجدول، والنوافذ قابلة للتمرير على الشاشات القصيرة. تفاصيل العيادة والتصدير لا تكشفان بيانات المرضى. زر التعطيل منفصل عن الحذف ولا يُستدعى تلقائيًا عند رفضه.

عقود API، migration، سياسة الفترات والأعداد، الصلاحيات ومتطلبات التشغيل في [توثيق Laravel](../../backend/docs/clinics-api.md).

## إعادة الاختبارات

شغّل build وخادم Next محليًا، ثم اضبط TEST_BASE_URL إلى ذلك الخادم. اختبارات المتصفح ترفض المضيفين الخارجيين وتستعمل استجابات API اختبارية؛ تحتاج Chromium أو `PLAYWRIGHT_CHANNEL=msedge` على Windows.

```bash
npx tsc --noEmit
npm run lint
npm run build
npm run test:clinics
npm run test:shell
npm run test:dashboards
npm run test:ui
```

`CLINIC_CAPTURE=1` يعيد توليد الصور من اختبارات العيادات. اختبارات الواجهة تتحقق من التنقل، الصلاحيات الظاهرة، الرفض الفعلي للصفحة المباشرة عبر API، الأخطاء والمدخلات، فروق ارتباطات الأطباء، الحذف والتعطيل، التنزيل، استجابات متأخرة، لوحة المفاتيح والقياسات المحمولة. اختبار الدخول الحي الاختياري القديم يبقى مشروطًا بإعداداته الموثقة في auth-ui؛ نجاح اختبارات الاستجابات المحاكاة لا يُقدَّم على أنه اختبار شبكة حي.

## إصلاح مراجعة PR #8: تعارض التعديل وتاريخ البحث

عند CLINIC_VERSION_CONFLICT تبقى الحقول واختيارات الأطباء في المسودة، ويُمنع الحفظ حتى المراجعة. زر «جلب أحدث نسخة» يقرأ بيانات العيادة وصفحات الأطباء الحاليين وحالة الأطباء الذين غيّرهم المستخدم، ثم يتحقق من lock_version مرة أخرى. تغيّر النسخة أثناء القراءة يستلزم إعادة الجلب؛ لا تُستخدم بيانات من نسختين في مراجعة واحدة.

تعرض المراجعة قيمة بدء التعديل وأحدث قيمة والمسودة. أحدث القيم هي الافتراضية؛ يختار المستخدم صراحةً الحقول وارتباطات الأطباء التي يريد تطبيقها، ثم يعتمد الاختيارات ويعود إلى نموذج قابل للمراجعة قبل حفظ منفصل. لا يُغيّر lock_version وحده ولا تُعاد المسودة كاملة فوق عمل مستخدم آخر. التغييرات الطبية تُحسب مقابل الحالة الحالية، ولا ترسل إضافات أو إزالات مطابقة لها أصلًا. الطبيب الذي لم يعد متاحًا لا يُعاد تطبيق اختياره؛ تعرض المراجعة السبب وتحافظ على ارتباطاته المخفية وتاريخه.

إعادة الجلب تحدث الجدول أو التفاصيل أيضًا، فلا تعيد فتح بيانات قديمة. فشل أي قراءة يبقي المسودة ويتيح إعادة المحاولة. الطلب مرتبط بعمر النافذة وسياق المنشأة؛ الإغلاق أو تغيير السياق يمنع النتيجة المتأخرة من تحديثهما. التعارض الثاني يمر بالمسار نفسه.

URL هو مصدر البحث والفلاتر والترقيم المعتمدة. الكتابة وحدها تنشئ مؤقتًا 300ms مرتبطًا بالرابط الحالي؛ الرجوع والتقدم وتغيير المنشأة يلغونه. لا يوجد تأثير يعيد كتابة قيمة محلية عند استعادة URL. يستخدم البحث `history.replaceState` المندمج مع useSearchParams في Next، ليظل الاستبدال داخل إدخال التاريخ نفسه ويتم فورًا دون انتقال مؤجل قد يعكس كتابة أحدث. لا يتحول البحث إلى push؛ تغيير الفلاتر يبقى replace، والتنقل إلى العيادة والمنشأة يبقى push. يظل التصدير معطلًا حتى تطابق نص البحث الظاهر مع الرابط، ويستعمل بعدها الفلاتر المعتمدة نفسها.

التحقق الفعلي لهذا الإصلاح فقط:

| الفحص | قبل الإصلاح | بعد الإصلاح |
| --- | --- | --- |
| اختبارا `regression:` | فشلا: غياب زر جلب أحدث نسخة؛ بقاء `first` بدل `second` بعد إدخال تاريخ فعلي | نجحا |
| اختبارات clinics + AppShell + dashboards + auth-ui | — | 41 ناجحًا من 42، منها 19 للعيادات؛ اختبار دخول حي اختياري واحد متجاوز لعدم ضبط بياناته |
| `npx tsc --noEmit` | — | نجح |
| `npm run lint` | — | نجح |
| `npm run build` | — | نجح |
| `git diff --check` | — | نجح |

شُغّلت اختبارات المتصفح على بناء Next المحلي عبر `TEST_BASE_URL=http://127.0.0.1:3101` و`PLAYWRIGHT_CHANNEL=msedge` بالأمر `node --test tests/clinics.test.mjs tests/app-shell.test.mjs tests/dashboards.test.mjs tests/auth-ui.test.mjs`. تغطي الاختبارات اختلاف الحقول، الارتباطات المتزامنة وغير المحملة وغير المتاحة، صفحات الأطباء، فشل إعادة الجلب، تغيّر النسخة أثناء الجلب والتعارض الثاني، الإغلاق وإعادة الفتح، النتائج المتأخرة، تاريخًا فعليًا بـpushState وback/forward، الرجوع أثناء debounce، وعدد طلبات البحث والتصدير والعودة من التفاصيل. عُوينت المراجعة على عرض 390px أيضًا.

تستعمل هذه الاختبارات استجابات API محاكاة؛ لم يُشغّل اختبار Laravel أو اختبار شبكة حي ولم يحدث اتصال بقاعدة بيانات في هذا الإصلاح. لا تغيير في backend أو FastAPI أو migrations أو إعدادات الإنتاج.
